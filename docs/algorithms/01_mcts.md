# MCTS — поиск по дереву методом Монте-Карло

**Monte Carlo Tree Search.** Способ выбрать ход: проигрываем много вариантов будущего в симуляторе и смотрим, какой ход чаще ведёт к победе.

## Зачем

В позиции боя ~50 легальных ходов. После каждого — ходы других существ и броски кубиков. Перебрать всё дерево до конца боя невозможно.

MCTS строит дерево **постепенно** и тратит время на **перспективные** ветки. Ценность ходов оценивает усреднением результатов случайных доигрышей — отсюда «Монте-Карло».

## Обозначения

| Символ | Смысл |
|---|---|
| $s$ | позиция (узел дерева) |
| $a$ | ход из позиции $s$ |
| $N(s)$ | сколько раз симуляции проходили через $s$ |
| $N(s,a)$ | сколько раз из $s$ выбирали ход $a$ |
| $W(s,a)$ | сумма результатов этих симуляций |
| $Q(s,a) = \dfrac{W(s,a)}{N(s,a)}$ | средний результат хода $a$ — его оценка |
| $z \in \{-1, +1\}$ | итог доигрыша: поражение или победа |

## Одна симуляция — четыре шага

```
  1. Выбор          2. Расширение      3. Доигрыш         4. Обратный проход
     (s0)              (s0)               (s0)               (s0) ← обновить
     /  \              /  \               /  \               /  \
   (s1) ( )          (s1) ( )           (s1) ( )           (s1) ← обновить
    |                 |  \               |  \                 \
   ...               ... (new)          ... (new)            (new) ← обновить
                                              ⋮ случайные ходы
                                             z = +1
```

**1. Выбор.** От корня спускаемся по уже построенному дереву. В каждом узле берём ход с наибольшим значением **UCT** (UCB1 для деревьев):

$$
a^{*} = \arg\max_{a} \left[\, Q(s,a) + c \sqrt{\frac{\ln N(s)}{N(s,a)}} \,\right]
$$

- $Q(s,a)$ — **эксплуатация**: ход уже показал себя хорошо.
- Второе слагаемое — **исследование**: оно растёт у ходов, которые пробовали редко. При $N(s,a) = 0$ ход выбирается обязательно.
- $c$ задаёт баланс между ними. Для результатов в $[0,1]$ классическое значение — $c = \sqrt{2}$, на практике подбирается.

**2. Расширение.** Дошли до узла, у которого есть непопробованный ход. Добавляем в дерево один новый дочерний узел.

**3. Доигрыш (rollout).** Из нового узла доигрываем бой до конца быстрой **политикой доигрыша**: случайной или простым скриптом. Получаем итог $z$.

Вместо доигрыша до конца можно остановиться через $d$ ходов и применить **оценочную функцию** $\hat{V}(s)$, например разницу долей оставшегося HP сторон.

**4. Обратный проход.** Поднимаемся по пройденному пути и обновляем каждый узел:

$$
N(s) \leftarrow N(s) + 1, \qquad
N(s,a) \leftarrow N(s,a) + 1, \qquad
W(s,a) \leftarrow W(s,a) + z_{\text{side}(s)}
$$

где $z_{\text{side}(s)}$ — итог **с точки зрения стороны, которая ходила в $s$**. Для героев победа героев — $+1$, для монстров та же победа — $-1$.

## Выбор хода

После $n$ симуляций (бюджет на ход) делаем ход, который посещали чаще всего:

$$
a_{\text{ход}} = \arg\max_{a} N(s_0, a)
$$

Число посещений надёжнее, чем $Q$: у редко посещённого хода $Q$ может быть случайно завышено.

## Кубики: узлы случая

В шахматах после хода позиция определена. У нас «атака мечом» может закончиться промахом, попаданием или критом. Поэтому в дереве два типа узлов:

```
[позиция] ──ход──▶ (случай) ──исход o с вероятностью p(o)──▶ [позиция]
```

- **Узел решения** — ход выбирает сторона, по формуле UCT.
- **Узел случая** — исход не выбирается, а **сэмплируется** по вероятностям из симулятора: $o \sim p(o \mid s, a)$.

Ценность узла случая — среднее по исходам:

$$
Q(s,a) = \sum_{o} p(o \mid s,a)\, V(s'_o)
$$

MCTS оценивает это среднее автоматически: исходы сэмплируются с их частотой.

Если исходов слишком много (урон $2\text{d}6 + 3$ даёт 11 значений, а на атаку бывает несколько бросков), похожие исходы группируются. Например, «промах / попадание / крит / цель упала».

## Чей ход

В D&D стороны не чередуются строго: порядок задаёт инициатива, и герой может ходить два раза подряд. Поэтому каждый узел хранит, **какая сторона ходит**. Обратный проход использует итог с точки зрения этой стороны.

## Что даёт MCTS в проекте

| Что | Откуда |
|---|---|
| Бот без обучения | Выбор хода по $N(s_0, a)$ |
| **Лучшие ходы** с оценкой | Таблица $Q(s_0, a)$ и $N(s_0, a)$ в корне |
| **Оценка позиции** | $V(s_0) \approx \sum_a \frac{N(s_0,a)}{N(s_0)}\, Q(s_0,a)$ |
| Основа для AlphaZero | Те же 4 шага; меняется формула выбора и доигрыш (см. ниже) |

Пример результата в корне после 400 симуляций:

| Ход | $N(s_0,a)$ | $Q(s_0,a)$ |
|---|---:|---:|
| Атака по раненому гоблину | 212 | 0.41 |
| Fire Bolt по шаману | 118 | 0.33 |
| Отход за укрытие | 52 | 0.12 |
| Атака по целому гоблину | 18 | −0.05 |

## Плюсы и минусы

**Плюсы:**
- Без обучения и без данных.
- Работает с любым симулятором, где можно скопировать состояние и сделать ход.
- Чем больше бюджет, тем сильнее; можно остановить в любой момент.

**Минусы:**
- Каждый ход стоит $n$ симуляций с доигрышами — медленно.
- Качество зависит от политики доигрыша: случайные доигрыши в D&D очень шумные.
- Огромное ветвление: 50 ходов × исходы кубиков.

## Связь с AlphaZero

AlphaZero — это MCTS, где две вещи заменены нейросетью $f_\theta(s) = (\mathbf{p}, v)$:

- **Доигрыш** заменён оценкой позиции $v$.
- **Формула выбора** UCT заменена на PUCT с подсказкой сети $P(s,a)$:

$$
a^{*} = \arg\max_{a} \left[\, Q(s,a) + c \, P(s,a) \frac{\sqrt{N(s)}}{1 + N(s,a)} \,\right]
$$

Подробно — в отдельном документе, когда дойдём до AlphaZero.

## Требования к движку

- Копировать состояние: $s \mapsto s'$ без изменения оригинала.
- Список легальных ходов в любой позиции.
- Для каждого хода — распределение исходов $p(o \mid s, a)$ или возможность их сэмплировать.
- Скорость: тысячи ходов в секунду, потому что на один реальный ход уходят сотни симуляций.
